# Abstract

Users of shared clusters must state how much CPU and memory a job needs before it runs. Because a request that is too low can cause throttling, out-of-memory termination or eviction, users tend to request more than their jobs use, and the unused reservations reduce the capacity available to other jobs. Many cluster jobs recur, so the usage of earlier runs is evidence about the next one. Existing approaches to this problem mostly act at runtime, require changes to the scheduler or rely on online experimentation. This project presents TraceAdvisor, an offline, trace-driven system that recommends CPU and memory for the next run of a recurring workload using only information available before that run starts.

TraceAdvisor compares seven policies: the user's request; the mean and the 90th, 95th and 99th percentiles of earlier usage; a machine learning (ML) prediction; and a Hybrid policy that takes the larger of the ML prediction and a historical percentile, so that the prediction can raise but never lower the historical safeguard. The system is applied to Google ClusterData 2019 and the Alibaba GPU Cluster Trace 2020 through dataset-specific adapters that map each trace into a shared canonical schema. Policies are evaluated by replaying each trace in time order and are measured by violation rate, shortfall, waste and utilization; all selection decisions are made on a validation period and locked before a held-out test period is scored once.

On the Google test period, Hybrid had the lowest rate of runs whose CPU or memory usage exceeded the recommendation, 12.36%, compared with 14.67% for the 99th percentile and 54.47% for the user's request, while keeping the waste of its 95th-percentile safeguard. On Alibaba, Hybrid reduced the violation rate of its 99th-percentile safeguard from 6.45% to 3.77% for CPU and from 3.44% to 3.15% for memory at almost the same memory waste. The ML prediction alone was the least wasteful policy on both datasets but under-provisioned between one run in three and one run in two. The results show that historical percentiles and a learned prediction are complementary: the percentile limits under-provisioning, and the prediction adds capacity where the history underestimates the next run.

**Keywords:** cluster workloads, resource recommendation, CPU and memory sizing, production traces, machine learning, trace replay
